    \section*{Abstract} \label{sec:abs}

    In recent years the role of the gut micro-biome in health has been elucidated \cite{ross_interplay_2024}.
    \newline

    \section{Introduction} \label{sec:intro}

    In this assignment we try to compare different \textit{regressors} for \textit{BMI} depending on the prevalence of and diversity of species of the gut micro-biome.
    \newline

    \subsection{Body mass index} \label{subsec:bmi}

    The body mass index (BMI) is a metric derived from the mass, weight and height of a person in $\frac{km}{m^2}$. The world health organization (WHO) \cite{noauthor_world_nodate} has an official categorization of different values of the BMI per age group. The BMI can be a useful estimator for ones physical condition and health \cite{armet_rethinking_2022}.
    \newline

    \subsection{Gut microbiome} \label{subsec:micro}

    The gut microbiome is the sum of populations of microorganisms that live in the digestive track. This term may refer to only the populations on a binary, exists/ does not exist scale but here we refer to it as not only existence but also quantification of populations of microorganisms. The importance of the presence of these colonies has to do with their role in adding elements or altering elements of the sum of all metabolic pathways originating from the digestive track.
    \newline

    \section{Methods} \label{sec:methods}

    \subsection{Implementation} \label{subsec:impl}

    All results were created in the \textit{Python} programming language \cite{noauthor_3132_nodate}.
    \newline

    \subsection{Models} \label{subsec:models}

    Three different \textit{regressors} were used in the analysis.
    \newline

    Models:
    \newline

    \begin{enumerate} \label{enm:models}
        \item Bayesian Ridge
        \item Support Vector Regression
        \item Elastic Net
    \end{enumerate}

    Models were imported from the \textit{sklearn} \cite{noauthor_scikit-learn_nodate} library in \textit{Python} \cite{noauthor_3132_nodate}.
    \newline

    \subsection{Evaluation metrics} \label{subsec:metrics}

    Four evaluation metrics were chosen
    \newline

    \begin{enumerate} \label{enm:metrics}
        \item Root mean squared error
        \item Mean absolute error
        \item R2 score
        \item Median absolute error
    \end{enumerate}

    The Root mean squared error, Mean absolute error, R2 score were chosen as evaluation metrics because they are listed as mandatory and the Median absolute error because we have seen the distributions of the pairs of features and we know:
    \newline

    \begin{enumerate} \label{enm:metricReasons}
        \item The categorical data is not going to be in the final data, but in the final metadata.
        \item Some sets of features contain what seem like outliers.
        \item We have no median based metric till now to compensate
    \end{enumerate}

    As a result of knowing about outliers a median metric must be included to compare with the non-median metrics.
    \newline

    \subsection{Confidences} \label{subsec:conf}

    $1000$ iteration \textit{bootstrapping} was done on models for evaluation along with repeated \textit{k-fold cross validation} for $50$ folds, $20$ iterations.
    \newline

    The \textit{sklearn} library \cite{noauthor_scikit-learn_nodate} does not contain a \textit{bootstrapping} function that we can use to call on our models. A protocol was written at \href{https://github.com/ArisPodotas/Assignment-1-MLICB/blob/main/src/functions.py}{our source files}.
    \newline

    Three distinct \textit{bootstrap} implementations were assessed.
    \newline

    \begin{enumerate} \label{enm:bootstrap}
        \item Only altering the training set
        \item Only altering the validation set
        \item Altering both the training and validation set
    \end{enumerate}

    For all models all three were used.
    \newline

    All files can be found at \href{https://github.com/ArisPodotas/Assignment-1-MLICB/tree/main}{this repository}.
    \newline

    \subsection{Figures} \label{subsec:figs}

    Figures were generated from the \textit{matplotlib} \cite{noauthor_matplotlib_nodate} library, all implementations are available at \href{https://github.com/ArisPodotas/Assignment-1-MLICB/blob/main/src/functions.py}{our source files}.

    In all box plots the dotted green line denotes the mean value and the orange line denotes the median.

    \subsection{Data transformations} \label{subsec:transforms}

    Categorical values like the \textit{Sex} category were cast to categorical numerical values.
    \newline

    Since the data was not z-scale normalized a z-scale normalization was done on the micro-organism colonies.

    \subsection{Feature selection} \label{subsec:fselect}

    Columns such as \textit{Host age} were removed from the final data before baselines were established
    \newline

    List of removed features:
    \newline

    \begin{enumerate} \label{enm:colms}
        \item Unamed 0
        \item Experiment type
        \item Disease Mesh ID
    \end{enumerate}

    Then the features:
    \newline

    \begin{enumerate} \label{enm:metadata}
        \item Project ID
        \item Sex
        \item Host age
    \end{enumerate}

    Were considered metadata for our models and a baseline was created with these in mind as was without them.
    \newline

    Once the baseline was established the feature selected models used a principal component analysis to keep $95\%$ of the total variance. This left only $95$ features in the dataset.
    \newline

    \subsection{Hyper parameter optimization} \label{subsec:optuna}

    The library \textit{optuna} \cite{noauthor_optuna_nodate} was used to search for model best parameters.

Not only are negative values of the BMI not allowed but values that range $\leq 10$ are very unlikeley to impossible. There is also something evidently wrong with the model according to the k-fold cross validation results Figure~\ref{fig:baselineKfold} as the \textit{r2} score is negative which is indicative of poor guessing.
    \newline

    The other two \textit{regressors} suffer from a seperate problem, one that might render them uniquely worse than the Bayesian ridge, that being that the prediction range is very narrow and misses a large portion of the validation set and even the development set. Their metrics may not be too altered as a result of this since the predictions within range are plentiful and accurate. This is something to keep note of.

    \subsection{Feature selection} \label{subsec:fs}

    A function to compare the evaluation metrics of two consecutive models has been written in \href{https://github.com/ArisPodotas/Assignment-1-MLICB/blob/main/src/functions.py}{our source files} for a more analytical comparison of the steps we take. The funciton takes two distributions of evaluation metrics and calculates the difference of the two distributions, resulting in one final distribution. This final output will be a $0$ mean unit variance Gaussin should there be no difference between the two models.

    These results have better consistency when it comes to the bounds of the predictons (the maximum and minimum prediction of all models but mainly the Bayesian ridge). The evaluation metrics imply that this is not just a visual difference but that the models have performed better on the data once their inputs have been processed with a feature selection method \ref{subsec:fselect}. The difference is not substantial but it is notable. One thing to notice is that the upper predictions is the one that has changed the most from the previous models. There is a tendency thus far to predict lower values rather than higher ones. This time we miss the highest BMI (being $60$) in the validation set in the prediction range. This is something that cannot be helped since the data point in question is of low representation and only in the validation set.
    \newline

    Now that the bounds of all models are shorter we can see that the Elastic net seems to be on average not capturing the distribution properly but is sometimes (some bootstrap iterations) capturing the actual range of the dev set on the lower bound.

    \section{Conclusions} \label{sec:conc}

    Our final "winner" model seems to have a good distribution of it's predictions for the training set that was used, it's metrics leave something to be desired however considering that each step did not improove them much. Seeing as the \textit{r2} score is negative we cannot say that this model does "good" predicitons. It would seem that this problem is not solvable to a satisfying degree with the given data that has been offered as of this assignment.
